# Translating

Translation workflow, data formats and text-safety rules for the zh-CN
localization. All translation/authoring data lives under `locales/zh-CN/source/`.

---

# 1. Where the translation data lives

```text
locales/zh-CN/source/
  zh_draft_ep01.json … zh_draft_ep12.json      # movie / cutscene subtitles (glyph atlas)
  zh_draft_archive.json                        # archive-video subtitles (glyph atlas)
  zh_draft_label.json                          # launcher labels (glyph atlas)
  zh_draft_chapter_s01.json … s25.json          # chapter system text (glyph atlas, sNN0)
  zh_draft_common.json                         # shared archive names / episodes / templates
  zh_draft_sxx1.json                           # GUIDE / TUTORIAL (sNN1, nested runs)
  archive_zh.json          + archzh/batch_*.json   # in-game documents (baked image)
  manual_zh.json                               # in-game manual (baked image)
  d12/…                                        # status / map / option menu text (baked image)
  i18n_src/d5,d6,d8,d9,d10,d11,d13,manhead,icon,etxt.json  # menu/UI baked-text sets
  mask_job_{mission,pause,results,ui2,archhead}.json + _d7_job.json  # standalone mask jobs
  label_zh.json, s09_over.json                 # label texts; chapter-9 supplementary text
  patch_common.json, patch_font.json           # deploy manifests (generated by builders)
  font_cfg.json, font01_zh.glyphspec.json      # font + global-atlas spec
  chap_templates.json, vocab*.json, subvocab*.json, jp_diff.json  # JP decoder dictionaries
  jp_decode_fixes.json                         # corrections for mis-transcribed vocab cells (see docs/PITFALLS.md #23)
```

Do not mix unrelated domains into one file. Do not edit generated manifests
(`patch_*.json`) by hand — they are produced by the builders.

> These files are copies of the original `_hanhua/work/` sources. Some contain
> intermediate structure from the tools; edit only the human-language fields
> described below.

# 2. The four text channels (how to edit each)

| Channel | Source files | Field to edit | Notes |
|---|---|---|---|
| Glyph atlas (FONTDATA) | `zh_draft_ep*.json`, `zh_draft_archive.json`, `zh_draft_label.json`, `zh_draft_chapter_s*.json`, `zh_draft_common.json` | `lines[].text` (zh) | `lines[].src`/`name` are reference/identity — do not change |
| GUIDE/TUTORIAL | `zh_draft_sxx1.json` | per-record run arrays | see §4 |
| Baked images | `archive_zh.json`, `manual_zh.json`, `d12/*.json`, `i18n_src/*.json`, `mask_job_*.json` | `zh`/`text` fields | layout metadata must not change |
| UTF-8 plain text | `i18n_src/etxt.json` (+ `system_zh.dat`, `header_*_zh.txt`) | `zh`/replacement pairs | keep line counts |

The **export view** (`_i18n_export.js` → `locales/zh-CN/translator-view/`) flattens
all of the above into 11 JSON files (`01_movie_subtitles.json` …
`11_plaintext.json`) for simpler editing. Each entry is `{ id, jp, zh, ref?, meta? }`:

- **`id`** — stable; do not change (import maps rows back by `id`).
- **`jp`** — Japanese original / reference; read-only.
- **`zh`** — the translation; **edit this only**.
- **`ref`** — for baked textures, the original Japanese texture PNG under
  `translator-view/refs/` (for text with no stored JP).
- **`meta`** — layout parameters (size/x/y/align); do not change.

Run `导出汉化.bat` to produce the export view, edit `zh`, then `导入汉化.bat` to
apply. Both share the full rebuild pipeline with `-Task rebuild`.

# 3. Text-safety rules (protect machine-readable tokens)

Treat these as protected; do not translate, delete, reorder or normalize them:

- record/segment control sequences (glyph atlas): `FF FD <u16> FF FC`
  (`<u16>` = `0x181C` for sNN0/movie/archive, `0x1216` for sNN1);
- the record terminator `0xFFFF`;
- glyph-index streams and per-record width fields (managed by the tools);
- record names / `id`s / `archive_names` Japanese keys (used as internal keys);
- line-break / segment separators inside `zh` values (see §4);
- the leading `#` of comment lines in `render_setting.txt`.

The draft notation **`◇`** (decoder miss) and **`※`** (uncertain note) must never
reach the game; the importer strips them, but clean drafts are preferred so the
data stays reviewable.

---

# 4. Line breaks & special separators

- Chapter/movie/archive drafts: `text` is a single string. A display **line
  break** is written as `\n`; the importer emits the corresponding multi-segment
  FONTDATA layout (one width field per line). Restore a break only where the
  Japanese original had one — do not invent breaks, and do not add a break that
  makes a record too long for its slot (the importer falls back to one line, and
  reports overflow under `work/import/`).
- `zh_draft_sxx1.json`: each record is a list of **segments** (lines); within a
  segment, glyph runs are separated by `␟` (U+241F). Button icons are inserted by
  the writer — **never type icons yourself**.
- Baked-text `d12` entries: multi-line uses `\n`.
- Plain-text containers: keep the **same number of lines** as the original.

---

# 5. Capacity limits (critical)

- **FONTDATA record**: `bodyLen = (style ? 4 : 0) + 2*len + 2 ≤ original room`.
  If a translation overflows, shorten it. The importer emits `_cap_*.txt` /
  `_fitfail.txt` diagnostics under `work/import/` on failure.
- **Atlas cells**: the number of *glyphs not yet in the atlas* must not exceed the
  free cells (movie/archive/sNN0 = 378; sNN1 = 28×(H/22)). Deleting translations
  does **not** free cells; translating more can unlock protected cells.
- **Baked DDS replacement** must not exceed the original archive entry size
  (zero-relocation); the packer allows growth only up to the next entry.
- Long strings in baked textures may auto-shrink font size; extreme cases clip.

# 6. Terminology & consistency

Character names, place names and proper nouns must be consistent across **all
channels** (subtitles, chapter/UI text, documents, baked menus, item names).
The tables below are the canonical zh-CN glossary. The **source of truth is the
current `translator-view/`** — translation edits are made and committed there.
Where an older `source/` draft disagrees, the glossary wins: treat the draft as
stale and correct it on the next import.

Cross-cutting rules:

- The name interpunct is the middle dot `·` (`霍华德·莱特`), never `・`/`•`.
- Once a proper noun has a canonical form, keep those exact characters
  everywhere; do not paraphrase or split it.
- `マナ` (the religion and its symbols) is rendered `真鱼`, **not** by phonetic
  transliteration — hence `マナ字架` → `真鱼字架`, not `玛娜字架`/`玛纳字架`.
- Do not merge identical JP strings blindly; identical JP text can carry
  different meanings.

## 6.6 Corrected transcription: 羽生蛇村's district name

The district name in the 羽生蛇村 address is `三隅` everywhere (`三隅郡`). Some
archive pages (`a33`, the newspaper) had been mis-transcribed as `三隈` in the
`jp` reference field. Re-checked against the original archive-page masks
(`work/archdds/…`), the originals are indeed `三隅`, so every occurrence — `jp`
and `zh` alike — was unified to `三隅`.

Additional standing rules:

- **Item names** must match the authoritative names baked in
  `menu/jp/main_status/{weapon,item}_name/name_i_*.dds` (translated in
  `d12/trans.json`). The three text systems `AC_CHANGENAME_*`,
  `AC_PICK_UPNAME_*` and `GET_ITEMNAME_*` must agree (`_itemfix.js` enforces
  this; `I_EV_*` is skipped by design).
- `ARCHIVE030` intentionally keeps the Japanese `ろ` (phonetic Uroboros spelling,
  `圣画 -虚母ろ主-`); it is whitelisted in the audit. The **document body** for
  the same word uses `虚母吕主`.

# 7. Bilingual textures

`main_map` and the time axis are bilingual: `*_jp` (Japanese line) is translated
to Chinese; `*_other` (English line) is **restored to the original English**.
After any batch regeneration, run:

```text
node _revertpatch.js "place_other" "time_other"
```

This is part of `_pipeline.js`, but run it manually if you regenerate masks
outside the pipeline.

---

# 8. Encoding

- Repository/authoring files are **UTF-8**.
- The build converts to each runtime requirement (glyph indices, UTF-8, or
  Shift-JIS for `render_setting.txt`).
- Do not save runtime files in a different encoding for convenience.

---

# 9. Placeholders / numbers / punctuation

Fixed-format tokens (`%s`, `%d`, numeric values, bracketed names like `【…】`)
must survive translation. Full-width vs half-width punctuation follows the
project style (Chinese full-width punctuation; `·` for name interpunct;
`—` is the preferred dash — the legacy `-`/`ー` usage is under review, see
`docs/KNOWN_ISSUES.md`).

---

# 10. Changing the font

```text
node build.ps1 -Task rebuild -Font "<font name>" -Bold 0
# or: node tools/_setfont.js "<font>" --rebuild
```

This rewrites `font_cfg.json` and re-renders every atlas and baked texture, then
deploys and refreshes `dist`. After a large font change, visually re-check
`sXX1`/`label` alignment and the longest lines.

# 11. Translation QA

Automated (run before release, see `BUILDING.md` §10):

- `_validate_i18n.js` — **runs automatically** on `导出汉化.bat` (after export)
  and `导入汉化.bat` (before writing; an ERROR aborts the import unless `--force`).
  It flags `◇`/`※` (font channels), stray kana, control characters, placeholder
  mismatches and global-font missing glyphs, naming the **view file, entry `id`
  and the offending sentence** (e.g.
  `09_menu_d12.json :: d12::menu/…/s15_object01_02.dds :: JP_KANA :: "…"`). The
  import also surfaces the build diagnostics `work/import/_fitfail.txt`,
  `_capskip.txt` and `_cap_*.txt` (glyph-atlas records that do not fit).
- `_subaudit.js` — residual Japanese / unmapped glyphs across all deployed tables
- `_itemaudit.js` / `_itemfix.js` — item-name consistency
- `_chapaudit.js`, `_jmkaudit.js`, `_magicscan.js`, `_finalaudit.js` — record
  coverage
- `_depcheck.js` — deployment reached HDD + mirror

Manual: in-game review in RPCS3 (clipping, context, speaker, subtitle timing).

---

# 12. Adding another locale

1. Create `locales/<locale>/source/` with the same file layout.
2. Set `locale` in `config.local.json`.
3. If the target script needs glyphs absent from the base atlases / global font,
   extend them (`glyphgen.js`, `_tbladd.js`) — the mechanism already supports
   arbitrary glyphs; only the specific code points differ.
4. Re-run the audits with adjusted whitelists (kana/character expectations).

No source-code change to the framework is required merely to add a locale.
